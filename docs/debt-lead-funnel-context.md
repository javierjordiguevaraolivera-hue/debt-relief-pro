# Debt Lead Funnel Context

This document records the agreed data model and expected lead-delivery flow for
the future English debt funnel. It is implementation context, not executable SQL.

## Current Scope

- The future form changes apply to the English funnel at `/en/apply`.
- The current Spanish affiliate flow must remain unchanged.
- The English flow will stop redirecting qualified users to an affiliate funnel.
- The English flow will collect lead data and persist it in Supabase.
- The form fields and step structure have not been designed yet.
- Existing English and Spanish affiliate URL environment variables must remain
  available for other funnels.
- Supabase credentials are supplied through `.env.local` and Vercel environment
  variables. Credentials must never be committed or exposed to client code.

## Expected Submission Flow

The reference flow from the existing `/debt-v1` and `/debt-v2` funnels is:

1. The frontend sends a `POST` request to `/api/lead`.
2. The server validates the anti-submit token, request origin, payload, and phone.
3. The server inserts the primary record into `public.debt-leads`.
4. The server inserts the technical record into `public.debt-leads-metadata`,
   linked through `lead_id`.
5. The API responds with `leadId` and `applicationNumber`.
6. The server delivers the lead to n8n in the background when
   `N8N_DELIVERY_WEBHOOK_URL` is configured.
7. A successful delivery changes `lead_status` to `sent`.
8. A failed delivery changes `lead_status` to `delivery_failed`.
9. Without a configured webhook, `lead_status` remains `new`.

The exact mechanism for reliable background work in this Next.js/Vercel project
must be selected during implementation.

## Database Schema Reference

The supplied schema is for context only and must not be run as a migration.
Hyphenated table names require quoted identifiers in SQL:
`"debt-leads"` and `"debt-leads-metadata"`.

### `public.debt-leads`

Primary lead and contact data:

| Column | Type | Expected use |
| --- | --- | --- |
| `id` | `uuid` | Primary key generated by Supabase |
| `first_name` | `text` | User first name |
| `last_name` | `text` | User last name |
| `email` | `text` | Normalized email |
| `phone` | `text` | Validated US phone normalized to 10 digits |
| `mobile` | `text` | Same normalized value as `phone` |
| `address1` | `text` | Selected or entered street address |
| `city` | `text` | City, when available |
| `state` | `text` | Normalized state abbreviation when applicable |
| `zipcode` | `text` | ZIP normalized to 5 digits |
| `total_debt_amount` | `text` | Debt range selected in the funnel |
| `dob` | `date` | Date of birth as `YYYY-MM-DD` |
| `ssn` | `text` | Used by `/debt-v1`; empty or null for `/debt-v2` |
| `funnel_id` | `text` | Funnel identifier such as `debt-v1` or `debt-v2` |
| `domain` | `text` | Request domain or `NEXT_PUBLIC_LEAD_DOMAIN` |
| `source` | `text` | `NEXT_PUBLIC_LEAD_SOURCE` or frontend tracking source |
| `language` | `text` | `NEXT_PUBLIC_LEAD_LANGUAGE` or funnel language |
| `sub1` | `text` | Unified value from `sub1` or `Sub1` |
| `sub2` | `text` | Unified value from `sub2` or `Sub2` |
| `trustedform_cert_url` | `text` | Historical field, currently unused |
| `lead_status` | `text` | Defaults to `new`; later `sent` or `delivery_failed` |
| `created_at` | `timestamptz` | Supabase timestamp |
| `updated_at` | `timestamptz` | Supabase timestamp |

| Column | Type | Expected use |

### `public.ringba_call_events`

Stores pay-per-call and Ringba events. Important fields include the linked
`lead_id`, funnel and Ringba identifiers, event/conversion status, call duration,
phone numbers, payout, revenue, and the complete `raw_payload`.

It is currently used in particular to record `printed_number` captured by a
thank-you page or call popup.

### `public.environment_variables`

Dynamic configuration stored in Supabase:

- `NEXT_PUBLIC_PAY_PER_CALL_STATUS`: `ON` or `OFF`
- `NEXT_PUBLIC_PAY_PER_CALL_START_TIME`: start time as `HH:MM`
- `NEXT_PUBLIC_PAY_PER_CALL_END_TIME`: end time as `HH:MM`
- `NEXT_PUBLIC_RINGBA_CAMPAIGN_ID`: Ringba campaign ID
- `NEXT_PUBLIC_PAY_PER_CALL_PHONE_NUMBER`: fallback phone number

With PPC set to `OFF`, the normal path is `lead` followed by n8n delivery.

## URL Parameter Rules

- Preserve every incoming URL parameter.
- Store parameters under
  `debt-leads-metadata.raw_payload.meta.urlParams`.
- Repeated parameters must be represented as arrays.
- Do not invent `utm_medium`; send an empty string to n8n when it is absent.
- Treat `sub1` and `Sub1` as the same value for the Supabase lead record.
- Treat `sub2` and `Sub2` as the same value for the Supabase lead record.
- The complete original capitalization and repetition can remain in
  `raw_payload.meta.urlParams`.

Example:

```json
{
  "utm_medium": "paid",
  "sub1": "abc",
  "Sub2": "xyz"
}
```

## n8n Delivery Contract

Delivery uses `N8N_DELIVERY_WEBHOOK_URL` and has this top-level shape:

```json
{
  "event": "debt_lead_created",
  "data": {},
  "metadata": {},
  "urlParams": {}
}
```

`data` contains:

- `lead_id`
- `application_id`
- `first_name`
- `last_name`
- `email`
- `phone`
- `mobile`
- `address1`
- `city`
- `state`
- `zipcode`
- `total_debt_amount`
- `dob`
- `ssn`

`metadata` contains:

- `funnel_id`
- `domain`
- `source`
- `language`
- `sub1`
- `sub2`
- `utm_medium`
- `url`
- `landing_url`
- `referrer_url`
- `sale_path`

`base_url` is no longer sent.

## Security and Data Handling Notes

- All Supabase writes must happen server-side.
- A Supabase service-role key, if used, must never use a `NEXT_PUBLIC_` name.
- The public form must not insert directly into these tables.
- SSN and DOB are sensitive personal data. The English funnel must explicitly
  decide whether it needs SSN before adding that field.
- Do not log raw payloads containing PII.
- Origin and anti-submit controls must be enforced by the API, not only the UI.
- The two inserts need failure handling so a primary lead is not silently left
  without its metadata record.
- Rate limiting, duplicate detection, phone validation, and retention/access
  rules need concrete implementation decisions.
